# 2026-07-18 · Added Kimi adapter

## What happened

Alpha wants to use both Claude Code and Kimi interchangeably on AlphaBrain. The risk was two
sets of instructions falling out of sync. We chose a single-source-of-truth design instead.

## Decisions

- `CLAUDE.md` and `WORKFLOW.md` stay as the living instructions for both tools.
- Added `KIMI.md` as a thin adapter: it tells Kimi to read `CLAUDE.md` and `WORKFLOW.md`
  manually every session, then follow the same domain routing, ingestion, and write-back
  rules.
- Kimi will read `.claude/commands/` and `.claude/hooks/` directly when needed, rather than
  duplicating them under `.kimi/`.
- The learning loop: whichever tool finds friction updates `WORKFLOW.md` and logs it in
  `ops/CHANGELOG.md`; the other tool picks up the change on its next session.

## Files changed

- Created `KIMI.md`.
- Updated `ops/CHANGELOG.md` with the change record.
- Created `ops/progress/` to hold system-level session write-backs.

## Next steps / open questions

- Test the adapter on the next Kimi session to make sure it reads the right files in order.
- If new Kimi-specific tooling appears later, evaluate whether it still makes sense to keep
  everything in `.claude/` or whether to move commands/hooks to a neutral `ops/` location.
